# Experience 经验库格式模板

> 本文件是 `/review` 沉淀经验、各技能前置读取的**规则库**格式模板。
> 项目级 `./docs/EXPERIENCE.md` 与通用级 `~/.pd-workflow/general-experience.md` 只放可复用、可执行、可检查的规则；来源、证据、轮次、日期等历史一律留在复盘报告的「经验库变更清单」。
> 修改本文件即时生效，无需重新生成 SKILL.md。

## 项目级：`./docs/EXPERIENCE.md`

```text
# 经验库（项目级：<项目名>）

## 需求阶段经验

| 规则ID | 触发场景 | 经验细则（必须 / 禁止） | 检查点 | 适用模块 |
|---|---|---|---|---|

## 开发阶段经验

| 规则ID | 触发场景 | 经验细则（必须 / 禁止） | 检查点 | 适用模块 |
|---|---|---|---|---|
```

## 通用级：`~/.pd-workflow/general-experience.md`

```text
# 经验库（通用级）

## 需求阶段经验

| 规则ID | 触发场景 | 经验细则（必须 / 禁止） | 检查点 |
|---|---|---|---|

## 开发阶段经验

| 规则ID | 触发场景 | 经验细则（必须 / 禁止） | 检查点 |
|---|---|---|---|
```

## 字段规则

- **规则ID**：项目级用 `REQ-001` / `DEV-001`，通用级用 `G-REQ-001` / `G-DEV-001`；空节从 `001` 开始，按该节现有最大序号 +1，已退役序号不复用。复盘报告、技能读取和跨条目引用都使用该 ID。
- **触发场景**：一条规则什么时候适用，写可检索的条件或关键词（如「PRD 涉及金额计算与舍入」「拆票声明范围小于真实改动」）；不写具体 feature 名、日期、人名。
- **经验细则（必须 / 禁止）**：一条规则只写一个必须或禁止的动作，可执行、可检查；禁止「沟通要充分」「考虑要周全」类空话。
- **检查点**：如何判定已遵守；能落到文档节、代码位置、命令或评审清单。
- **适用模块**：`全部` 或 GLOSSARY 登记的 `feature-module`；多个模块用 `、` 分隔。通用级不设此列，默认适用于全部项目。

## 维护规则

- **只放规则**：不记录日期、来源 feature-slug、证据、复现次数、最后复现、最后核实；这些由复盘报告的「经验库变更清单」承担。
- **去重**：按「阶段 + 触发场景 + 规则语义」判断，不靠来源或次数；相似条目合并表述，保留既有规则 ID。
- **晋升**：项目级规则与具体仓库无关（换仓库仍成立）时复制进通用级，分配通用级规则 ID；项目级条目不做「已晋升」备注。
- **引入**：通用级规则要被任一项目消费时，由 `/review` 复制进该项目级经验库并分配项目级规则 ID；下游技能只读项目级文件。
- **退役**：触发场景已不存在、被新规则取代或不再成立的规则直接删除；删除原因与证据只记在复盘报告。项目级库随 Git 保留历史，通用级库的历史由复盘报告承担。
- **规则级不进本库**：根治方式是改流水线规则（模板 / fragment / 配置项）的经验，写入复盘报告「流水线改进建议」节，不在经验库中重复记录。
